# 주요 용어 안내

업비트 개발자 센터에서 사용되는 기본 용어들의 정의와 설명을 제공합니다.

## 거래소 서비스 관련 용어

### 페어(Trading Pair)

업비트에서 거래를 지원하는 자산의 쌍으로, 오더북이 운영되는 단위입니다.

매수·매도의 대상이 되는 기준 자산(Base Asset)과 해당 자산을 거래할 때 사용하는 호가 자산(Quote Asset)으로 구성되며, 페어 코드는 `{Quote Asset}-{Base Asset}` 형식으로 표기합니다.

| 예시        | 의미                                            |
| --------- | --------------------------------------------- |
| `KRW-BTC` | 원화로 비트코인을 매수하거나, 비트코인을 매도하여 원화로 교환하는 거래       |
| `BTC-ETH` | 비트코인으로 이더리움을 매수하거나, 이더리움을 매도하여 비트코인으로 교환하는 거래 |

### 마켓(Market)

동일한 호가 자산(Quote Asset)을 사용하는 페어들의 집합입니다.

업비트는 원화(KRW), BTC, USDT 마켓을 운영하며, 예를 들어 원화를 호가 자산으로 사용하는 모든 페어를 원화 마켓이라고 합니다.

### 통화(Currency)

원화(KRW)와 같은 법정화폐 또는 비트코인(BTC), 이더리움(ETH)과 같은 디지털 자산을 지칭하는 용어입니다.

통화 코드(Currency Code)는 각 자산을 구분하는 코드 문자열로, `KRW`, `BTC`, `ETH` 등이 있습니다.

### 포켓(Pocket)

업비트 계정 내에서 자산을 목적별로 구분하여 투자하고 관리하는 기능입니다.

기본으로 제공되는 메인포켓과 사용자가 추가로 생성할 수 있는 서브포켓으로 구분합니다.

| 구분                | 설명                                                                                                |
| ----------------- | ------------------------------------------------------------------------------------------------- |
| 메인포켓(Main Pocket) | 업비트 계정 생성 시 기본으로 제공되는 포켓입니다. 외부 입출금을 포함한 기본 거래 기능을 이용할 수 있으며, 계정 내 전체 포켓을 관리하는 마스터 권한을 받을 수 있습니다. |
| 서브포켓(Sub Pocket)  | 특정 목적에 따라 추가로 생성하는 포켓입니다. API Key에 부여된 권한 범위 내에서 독립적으로 동작하며, 외부 입출금은 제한됩니다.                       |

## 시세 관련 용어

### 캔들(OHLCV)

특정 페어에서 일정 기간 동안 발생한 거래의 시가(Open), 고가(High), 저가(Low), 종가(Close), 거래량(Volume)을 집계한 데이터입니다. 주로 차트 시각화와 시세 분석에 사용됩니다.

* **집계 기간:** 초, 분, 일, 주, 월, 연 단위로 구분합니다.
* **국문 명칭:** '봉'이라고도 하며, 초봉, 분봉, 일봉, 주봉, 월봉, 연봉과 혼용합니다.

분 캔들은 집계 간격에 따라 3분봉, 10분봉 등으로 세분화할 수 있습니다.

## WebSocket 관련 용어

### Public WebSocket과 Private WebSocket

업비트에서 실시간 데이터를 수신하는 WebSocket 연결 유형입니다. 인증 필요 여부와 제공하는 데이터에 따라 구분합니다.

| 구분                | 인증                         | 제공 데이터                          |
| ----------------- | -------------------------- | ------------------------------- |
| Public WebSocket  | 불필요                        | 현재가, 체결, 호가, 캔들 등 공개 시세 데이터     |
| Private WebSocket | API Key로 생성한 인증 토큰(JWT) 필요 | 내 주문 및 체결, 내 자산, 공지사항, 기술적 지표 등 |

Private WebSocket은 수신하려는 데이터에 따라 다음 Endpoint를 사용합니다.

| Endpoint                | 주요 제공 데이터               |
| ----------------------- | ----------------------- |
| `/websocket/v1/private` | 내 주문 및 체결, 내 자산, 공지사항   |
| `/websocket/v1/info`    | 기술적 지표 값, 기술적 지표 조건 이벤트 |

자세한 연결 방법과 인증 및 오류 처리에 관한 내용은 [WebSocket 사용 및 에러 안내](https://docs.upbit.com/kr/reference/websocket-guide) 문서를 참고하시기 바랍니다.

### 기술적 지표 값(Indicator)과 기술적 지표 조건 이벤트(Indicator Signal)

확정 마감된 캔들(봉)을 기준으로 계산하여 Private WebSocket으로 제공하는 기술적 지표 데이터입니다.

기술적 지표의 계산값을 제공하는 방식과 지정한 조건의 충족 여부를 이벤트로 제공하는 방식으로 구분합니다.

| 구분                              | 설명                            | 전송 시점                     |
| ------------------------------- | ----------------------------- | ------------------------- |
| 기술적 지표 값(Indicator)             | 선택한 기술적 지표의 계산값               | 설정한 캔들이 확정될 때마다           |
| 기술적 지표 조건 이벤트(Indicator Signal) | 지정한 기술적 지표 조건이 충족되었음을 알리는 이벤트 | 조건이 미충족 상태에서 충족 상태로 전환될 때 |

기술적 지표 조건 이벤트는 '기술적 지표 시그널'이라고도 합니다. 조건이 충족된 상태로 유지되는 동안에는 반복 전송되지 않으며, 조건을 벗어났다가 다시 충족하면 새로운 이벤트가 발생합니다.

지원하는 기술적 지표와 구독 방법은 [기술적 지표](https://docs.upbit.com/kr/reference/websocket-indicator) 문서를 참고하시기 바랍니다.

## 주문 관련 용어

### 주문(Order)과 체결(Trade)

**주문(Order)**&#xC740; 디지털 자산을 매수하거나 매도하기 위해 거래소에 제출하는 요청입니다. 페어, 가격, 수량, 주문 유형 및 거래 옵션 등을 지정할 수 있습니다.

**체결(Trade)**&#xC740; 매수 주문과 매도 주문이 서로 일치하는 조건으로 매칭되어 실제 거래가 실행되는 것을 의미합니다. 하나의 주문은 전체 또는 일부 수량이 체결될 수 있습니다.

* **부분 체결:** 주문 수량 중 일부만 체결된 상태입니다. 하나의 주문이 여러 번에 나누어 체결될 수 있습니다.
* **주문 잔량:** 주문 수량 중 아직 체결되지 않고 남아 있는 수량입니다.

### 지정가 주문, 시장가 주문, 최유리 지정가 주문

주문 생성 시 선택할 수 있는 주문 유형입니다.

| 주문 유형      | 설명                                                                                    |
| ---------- | ------------------------------------------------------------------------------------- |
| 지정가 주문     | 매수 또는 매도할 단가와 수량을 직접 지정하는 주문입니다.                                                      |
| 시장가 주문     | 현재 오더북에 등록된 반대 호가를 대상으로 즉시 체결을 시도하는 주문입니다. 매수 시에는 주문 총액을, 매도 시에는 주문 수량을 지정합니다.        |
| 최유리 지정가 주문 | 매수 시 최저 매도 호가, 매도 시 최고 매수 호가와 동일한 단가로 주문하는 방식입니다. 매수 시에는 주문 총액을, 매도 시에는 주문 수량을 지정합니다. |

자세한 내용은 [주문 생성](https://docs.upbit.com/kr/reference/new-order) 문서를 참고하시기 바랍니다.

### 스프레드(Spread)

오더북에서 최우선 매수호가(가장 높은 매수 가격)와 최우선 매도호가(가장 낮은 매도 가격) 사이의 가격 차이입니다.

### 메이커(Maker)와 테이커(Taker)

주문이 오더북에 유동성을 추가하는지, 기존 유동성을 이용해 즉시 체결되는지에 따른 구분입니다.

| 구분         | 설명                                  | 예시                             |
| ---------- | ----------------------------------- | ------------------------------ |
| 메이커(Maker) | 즉시 체결되지 않고 오더북에 새로운 호가를 추가하는 주문입니다. | 현재 최우선 매수호가보다 낮은 가격의 지정가 매수 주문 |
| 테이커(Taker) | 오더북에 등록된 반대 호가와 즉시 체결되는 주문입니다.      | 시장가 주문                         |

하나의 주문에서도 체결 상황에 따라 메이커와 테이커 체결이 각각 발생할 수 있습니다.

### Post Only

주문이 메이커로만 등록되도록 하는 주문 옵션입니다.

제출한 주문이 오더북의 반대 호가와 즉시 체결되어 테이커로 처리될 가능성이 있으면 주문 생성을 취소합니다.

### 자전거래 체결 방지(SMP)

동일한 사용자가 생성한 매수 주문과 매도 주문이 서로 체결되는 것을 방지하는 주문 옵션입니다.

자전거래가 발생할 수 있는 상황에서 설정한 SMP 유형에 따라 주문을 취소하거나 체결을 방지합니다.

자세한 내용은 [자전거래 체결 방지(Self-Match Prevention, SMP)](https://docs.upbit.com/kr/docs/smp) 문서를 참고하시기 바랍니다.

## 코인빌리기 관련 용어

### 코인빌리기(Lending)

회원이 원화(KRW) 또는 지원되는 디지털 자산을 담보로 맡기고, 업비트가 보유한 디지털 자산을 빌리는 서비스입니다.

자세한 내용은 [코인빌리기 개요](https://docs.upbit.com/kr/reference/lending-overview) 문서를 참고하시기 바랍니다.

### 포지션(Position)

코인빌리기 신청 1건으로 생성되는 이용 단위입니다.

빌린 자산과 맡긴 담보를 하나의 포지션에서 관리하며, 전액 상환, 담보상환 또는 강제상환으로 종료될 때까지 유지됩니다.

하나의 포지션에서 추가신청, 담보추가, 일부 상환이 여러 번 이루어질 수 있습니다.

### 담보자산(Collateral)

코인빌리기를 이용하기 위해 맡기는 원화(KRW) 또는 디지털 자산입니다.

담보로 맡긴 자산은 코인빌리기 이용 중 출금할 수 없으며, 포지션 종료 시 정산 후 남은 담보가 반환됩니다.

### 담보 인정 비율(Collateral Factor)

디지털 자산의 가격 변동성을 고려하여 담보 가치를 할인해 인정하는 비율입니다.

담보로 인정되는 금액(담보 인정금액)은 자산 유형에 따라 다음과 같이 계산합니다.

* **원화(KRW):** 액면금액
* **디지털 자산:** 원화 환산 평가금액 × 담보 인정 비율

### LTV(Loan-to-Value)

담보 인정금액 대비 빌린 자산의 원화 환산 평가금액 비율입니다. 업비트에서는 '렌딩비율'이라고도 하며, LTV가 높을수록 강제상환 위험이 커집니다.

**계산식**

LTV = 빌린 자산의 원화 환산 평가금액 ÷ 담보 인정금액 합계

* 이용수수료는 LTV 계산에 포함하지 않습니다.
* 신청 가능한 LTV 범위와 강제상환 기준 LTV는 자산별로 다를 수 있습니다.

### 평가가격과 실행가격

코인빌리기에서 자산의 가치를 평가하거나 실제 매매를 진행할 때 사용하는 가격입니다.

| 구분   | 설명 및 사용 목적                                                                |
| ---- | ------------------------------------------------------------------------- |
| 평가가격 | 빌린 자산과 담보자산의 가치를 평가하는 데 사용하는 가격입니다. LTV 계산, 대여한도 산정, 강제상환 여부 판단 등에 사용합니다. |
| 실행가격 | 담보상환 또는 강제상환 과정에서 반대매매가 발생할 때 실제 주문 체결에 적용되는 가격입니다.                       |

평가가격과 실제 주문 체결 시점의 실행가격은 다를 수 있으므로, 평가가격을 기준으로 예상한 금액과 실제 정산 결과가 다를 수 있습니다.

### 추가신청(Borrow More)과 담보추가(Add Collateral)

이용 중인 코인빌리기 포지션에서 빌린 수량이나 담보를 변경하는 요청입니다.

| 구분   | 설명                                        | 유의사항                               |
| ---- | ----------------------------------------- | ---------------------------------- |
| 추가신청 | 기존 포지션에서 빌린 자산과 같은 종류의 자산을 추가로 빌리는 요청입니다. | 최초 신청 시 정해진 만기일이 그대로 적용됩니다.        |
| 담보추가 | 최초 신청 시 설정한 담보자산을 추가로 맡기는 요청입니다.          | 담보추가 이후에는 해당 포지션에서 추가신청을 할 수 없습니다. |

담보추가로 담보 인정금액이 증가하면 LTV가 낮아질 수 있습니다.

### 상환(Repay), 담보상환(Repay with Collateral), 강제상환(Liquidation)

코인빌리기에서 빌린 자산을 상환하는 방식입니다. 상환 주체와 상환에 사용하는 자산에 따라 구분합니다.

| 구분   | 진행 주체             | 상환에 사용하는 자산      | 상환 범위    |
| ---- | ----------------- | ---------------- | -------- |
| 상환   | 회원 요청             | 빌린 자산과 같은 종류의 자산 | 일부 또는 전액 |
| 담보상환 | 회원 요청             | 맡긴 담보자산          | 전액       |
| 강제상환 | 업비트(회원의 추가 동의 없음) | 맡긴 담보자산          | 전액       |

* **상환:** 회원이 빌린 자산과 같은 종류의 자산으로 직접 상환하는 방식입니다.
* **담보상환:** 회원의 요청에 따라 맡긴 담보자산을 이용하여 빌린 자산을 전액 상환하는 방식입니다.
* **강제상환:** LTV가 강제상환 기준에 도달하거나 이용기간이 만료되는 등의 사유가 발생했을 때, 회원의 추가 동의 없이 상환을 진행하는 방식입니다.

### 반대매매

담보상환 또는 강제상환 과정에서 빌린 자산을 상환하기 위해 맡긴 담보자산을 처분하고, 필요한 자산을 매수하는 절차입니다.

반대매매 시에는 맡긴 원화(KRW)를 우선 사용하고, 부족한 경우 담보자산을 매도하여 확보한 원화로 빌린 자산을 매수합니다.

**유의사항**

* 시장 상황에 따라 주문은 한 번에 실행되거나 여러 번으로 나누어 실행될 수 있습니다.
* 시장 상황이나 거래 제한 등으로 필요한 수량을 모두 매수하지 못한 경우, 부족분에 해당하는 가치만큼 담보자산을 직접 차감하는 방식으로 정산할 수 있습니다.
* 정산 후 남은 담보자산과 원화(KRW), 초과 매수된 자산은 회원에게 반환됩니다.

담보자산의 매도 및 차감 순서는 [코인빌리기 이용자 가이드](https://support.upbit.com/hc/ko/search?utf8=%E2%9C%93\&query=%EC%BD%94%EC%9D%B8%EB%B9%8C%EB%A6%AC%EA%B8%B0)와 [코인빌리기 FAQ](https://www.upbit.com/lending/guide?tab=faq)를 참고하시기 바랍니다.

### 요청 상태와 포지션 상태

코인빌리기 요청의 처리 상태와 포지션의 이용 상태를 구분하는 개념입니다.

| 구분     | 설명                                                                             | 확인 API                                                                    |
| ------ | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------- |
| 요청 상태  | 신청, 추가신청, 담보추가, 상환, 담보상환 등 개별 요청의 처리 상태와 결과를 나타냅니다. 처리 중, 정상 처리, 실패 등으로 구분합니다. | [코인빌리기 요청 상태 조회](https://docs.upbit.com/kr/reference/get-lending-request) |
| 포지션 상태 | 생성된 포지션의 현재 이용 상태를 나타냅니다. 정상 이용, 이용 제한, 강제상환 진행 중, 종료 등의 상태로 구분합니다.            | [개별 코인빌리기 조회](https://docs.upbit.com/kr/reference/get-lending)            |

요청 상태와 포지션 상태는 서로 다른 정보입니다. 요청이 정상적으로 처리되었더라도 포지션의 현재 상태는 별도로 확인해야 합니다.
